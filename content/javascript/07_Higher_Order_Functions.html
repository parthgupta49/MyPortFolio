Chapter 6 — The JavaScript Codex | Week 2

The most beautiful part of JavaScript: functions as first-class citizens

1. What is a Higher-Order Function?

▼
Definition: A Higher-Order Function (HOF) is a function that does at least one of these two things:
  1. Takes another function as an argument (a callback), OR
  2. Returns a function from itself
That's it. Any function meeting one or both of these conditions is a HOF.

The Simplest Example:

function x() {
  console.log("Hello");
}

function y(fn) {   // y takes another function as argument
  fn();            // and calls it
}

y(x);              // Hello

// Here:
// x → callback function (the one being passed)
// y → higher-order function (the one accepting/calling it)

HOFs You've Been Using Already (Without Knowing):

FunctionWhy is it a HOF?
arr.map(fn)Takes a function as argument
arr.filter(fn)Takes a function as argument
arr.reduce(fn, init)Takes a function as argument
arr.forEach(fn)Takes a function as argument
setTimeout(fn, ms)Takes a function as argument
setInterval(fn, ms)Takes a function as argument
element.addEventListener(event, fn)Takes a function as argument
Promise.then(fn)Takes a function as argument

A HOF That Returns a Function:

function multiplier(factor) {
  return function(number) {       // ← returns a function
    return number * factor;
  };
}

const double = multiplier(2);   // double is now a function
const triple = multiplier(3);   // triple is now a function

console.log(double(5));   // 10
console.log(triple(5));   // 15

multiplier is a HOF because it returns a function. This is also how currying works (coming up in Ch 6.5).

🔑 Why do HOFs exist? Because JavaScript treats functions as first-class citizens — you can pass them around like any other value (numbers, strings, objects). Without first-class functions, HOFs would be impossible. Not every language has this — languages like older Java don't. It's what makes functional programming in JS possible.

2. First-Class Functions — The Foundation

▼

You covered this in Chapter 3 (Closures). Quick recap because it's the foundation of every HOF:

Functions in JavaScript can be:

  • Assigned to a variable — const fn = function() {};
  • Passed as an argument — setTimeout(myFn, 1000);
  • Returned from another function — return function() {};
  • Stored inside data structures — const arr = [fn1, fn2, fn3];

Anywhere you can put a number, string, or object — you can put a function. This ability is what "first-class" means, and it's what enables the entire universe of HOFs.

🎯 Interview line: "Higher-order functions are possible in JavaScript because functions are first-class citizens — they can be passed around and returned just like any other value."

3. Why HOFs Exist — The DRY Principle

▼

The classic circle example shows exactly why HOFs matter. Suppose you have radii of circles and need area, circumference, and diameter for each.

❌ The BAD Way — Copy-Paste Hell:

const radius = [3, 1, 2, 4];

function calculateArea(radius) {
  const output = [];
  for (let i = 0; i < radius.length; i++) {
    output.push(Math.PI * radius[i] * radius[i]);
  }
  return output;
}

function calculateCircumference(radius) {
  const output = [];
  for (let i = 0; i < radius.length; i++) {
    output.push(2 * Math.PI * radius[i]);    // ← only the formula changed
  }
  return output;
}

function calculateDiameter(radius) {
  const output = [];
  for (let i = 0; i < radius.length; i++) {
    output.push(2 * radius[i]);              // ← again, only the formula changed
  }
  return output;
}
What's wrong here? You've violated the DRY principle (Don't Repeat Yourself). ~90% of the code in these three functions is identical — only the formula inside the loop changes. If you need to add validation, error handling, or logging, you'd have to update it in 3 places.

✅ The GOOD Way — Extract the Logic Into a HOF:

const radius = [3, 1, 2, 4];

// Logic functions (small, single responsibility)
const area = (r) => Math.PI * r * r;
const circumference = (r) => 2 * Math.PI * r;
const diameter = (r) => 2 * r;

// The HOF — accepts the "logic" as a callback
function calculate(radius, logic) {
  const output = [];
  for (let i = 0; i < radius.length; i++) {
    output.push(logic(radius[i]));   // ← the logic is passed in
  }
  return output;
}

// Usage:
console.log(calculate(radius, area));
console.log(calculate(radius, circumference));
console.log(calculate(radius, diameter));
🔑 What just happened? The iteration logic (loop, push, return) is written once. The "what to do at each element" is passed in as a function. This is abstraction through functions — and it's essentially what map does internally.

In fact, calculate from above is basically a mini map. Watch:

// Native map does exactly what our calculate does:
console.log(radius.map(area));
console.log(radius.map(circumference));
console.log(radius.map(diameter));
🎯 The Big Insight: map, filter, and reduce are just well-designed HOFs that JavaScript built-in for you. Understanding why they exist (DRY + single responsibility) is more important than memorizing their syntax.

4. map — Transform Each Element

▼
Purpose: map transforms every element of an array using a function you provide, and returns a NEW array of the same length. It does NOT mutate the original.

Syntax:

const newArr = originalArr.map(function(element, index, array) {
  return /* transformed value */;
});

The callback receives up to 3 arguments — usually you only need the first (the current element).

Basic Example — Double Each Value:

const nums = [5, 1, 3, 2, 6];

const doubled = nums.map(function(x) {
  return x * 2;
});

console.log(doubled);   // [10, 2, 6, 4, 12]
console.log(nums);      // [5, 1, 3, 2, 6]  ← original untouched!

Shorter Syntax (Arrow Function):

// All three of these are IDENTICAL:

// Named function
function double(x) { return x * 2; }
nums.map(double);

// Anonymous function
nums.map(function(x) { return x * 2; });

// Arrow function (most common in modern code)
nums.map(x => x * 2);

The Visualization:

Original:  [5,  1,  3,  2,  6]
              │   │   │   │   │
              ↓   ↓   ↓   ↓   ↓  ← map runs the fn on each element
             ×2  ×2  ×2  ×2  ×2
              ↓   ↓   ↓   ↓   ↓
Result:    [10, 2,  6,  4,  12]  ← NEW array of same length

Real-World Example — Extract a Field from Objects:

const users = [
  { firstName: "Alok", lastName: "Raj", age: 23 },
  { firstName: "Donald", lastName: "Trump", age: 75 },
  { firstName: "Elon", lastName: "Musk", age: 50 },
  { firstName: "Deepika", lastName: "Padukone", age: 26 }
];

// Get an array of full names:
const fullNames = users.map(user => user.firstName + " " + user.lastName);

console.log(fullNames);
// ["Alok Raj", "Donald Trump", "Elon Musk", "Deepika Padukone"]

This pattern — extracting a specific field from an array of objects — is one of the most common uses of map in real code (especially in React, when rendering lists).

⚠️ Rules of thumb for map:
  • The new array is always the same length as the original.
  • You MUST return a value from the callback — else you'll get undefined in that slot.
  • The original array is never mutated. It returns a new array.
  • Use it when you want to transform data.

5. filter — Keep Only What Matches

▼
Purpose: filter keeps only the elements that pass a test (a predicate function that returns true) and returns a NEW array. The new array may be shorter — or even empty.

Syntax:

const newArr = originalArr.filter(function(element, index, array) {
  return /* boolean: true to keep, false to skip */;
});

Basic Example — Keep Only Odd Numbers:

const nums = [5, 1, 3, 2, 6];

const odds = nums.filter(x => x % 2 !== 0);

console.log(odds);   // [5, 1, 3]
console.log(nums);   // [5, 1, 3, 2, 6]  ← original untouched!

Visualization:

Original:  [5,   1,   3,   2,   6]
             │    │    │    │    │
             ↓    ↓    ↓    ↓    ↓   ← predicate runs on each
            odd? odd? odd? odd? odd?
             ✓    ✓    ✓    ✗    ✗
             │    │    │
             ↓    ↓    ↓
Result:    [5,   1,   3]         ← only the "kept" ones

Real-World Example — Filter Objects:

const users = [
  { name: "Parth", age: 25 },
  { name: "Deepika", age: 30 },
  { name: "Rahul", age: 17 }
];

const adults = users.filter(u => u.age >= 18);

console.log(adults);
// [
//   { name: "Parth", age: 25 },
//   { name: "Deepika", age: 30 }
// ]
⚠️ Rules of thumb for filter:
  • The callback MUST return a boolean (or something truthy/falsy).
  • Returned array can be any length from 0 to the original length.
  • Original array is never mutated.
  • Use it when you want to keep a subset of data.

6. reduce — Collapse an Array Into One Value

▼
The most misunderstood method of the three. The name "reduce" isn't intuitive. But once you get it, it's the most powerful HOF in JavaScript.
Purpose: reduce takes an array and boils it down to a single value. That value can be a number, string, object, or even another array.

Syntax:

const result = arr.reduce(function(accumulator, currentValue, index, array) {
  return /* new accumulator value */;
}, initialValue);

The Two Key Parameters:

ParameterWhat It Represents
accumulator (acc)The "running total" — carries the result forward through each iteration
currentValue (curr)The current element being processed (like arr[i])
initialValueThe starting value for acc (the second argument to reduce)

Example 1 — Sum of Numbers:

const nums = [5, 1, 3, 2, 6];

const total = nums.reduce((acc, curr) => acc + curr, 0);

console.log(total);   // 17

Step-by-Step Trace:

Initial:  acc = 0

Iter 1:   curr = 5  →  acc + curr = 0 + 5 = 5    →  acc becomes 5
Iter 2:   curr = 1  →  acc + curr = 5 + 1 = 6    →  acc becomes 6
Iter 3:   curr = 3  →  acc + curr = 6 + 3 = 9    →  acc becomes 9
Iter 4:   curr = 2  →  acc + curr = 9 + 2 = 11   →  acc becomes 11
Iter 5:   curr = 6  →  acc + curr = 11 + 6 = 17  →  acc becomes 17

Final:    17

Example 2 — Find Maximum:

const nums = [5, 1, 3, 2, 6];

const max = nums.reduce((acc, curr) => (curr > acc ? curr : acc), -Infinity);

console.log(max);   // 6

Here acc holds the "biggest number seen so far." We start with -Infinity so the first real number always wins.

Example 3 — Building an Array (yes, reduce can do this too):

const nums = [1, 2, 3, 4, 5];

const doubled = nums.reduce((acc, curr) => {
  acc.push(curr * 2);
  return acc;
}, []);

console.log(doubled);   // [2, 4, 6, 8, 10]

// This is what map does internally, more or less!

Example 4 — The Interview Classic (Grouping/Counting):

const users = [
  { name: "Alok", age: 26 },
  { name: "Donald", age: 75 },
  { name: "Elon", age: 50 },
  { name: "Deepika", age: 26 }
];

// Count how many users of each age:
const ageCount = users.reduce((acc, user) => {
  if (acc[user.age]) {
    acc[user.age] += 1;
  } else {
    acc[user.age] = 1;
  }
  return acc;
}, {});

console.log(ageCount);
// { "26": 2, "75": 1, "50": 1 }

This "collapse an array into an object of counts" is a classic reduce pattern. Once you can write this without looking, you truly understand reduce.

⚠️ What Happens Without an Initial Value?

const nums = [5, 1, 3, 2, 6];

// No initial value passed:
const total = nums.reduce((acc, curr) => acc + curr);
console.log(total);   // 17 — still works!

// What actually happened:
// Iteration 0: acc = nums[0] = 5 (first element becomes initial acc)
//              curr = nums[1] = 1
//              acc becomes 5 + 1 = 6
// Iteration 1: curr = nums[2] = 3, etc.

// ⚠️ DANGER — empty arrays throw:
[].reduce((a, c) => a + c);         // 💥 TypeError: Reduce of empty array with no initial value
[].reduce((a, c) => a + c, 0);      // 0 ✅ safe with initial value
🎯 Best Practice: Always pass an initial value. It makes your code safer (handles empty arrays) and makes your intent clearer.

7. forEach vs map — The Critical Distinction

▼
Interview classic — get this wrong and it's a red flag.

The Fundamental Difference:

forEachmap
ReturnsundefinedA new array
PurposeSide effects (log, modify DOM, call API)Transform data
Chainable?❌ No (returns undefined)✅ Yes (returns array)
Original arrayNever mutatedNever mutated

Proof:

const nums = [1, 2, 3];

const a = nums.forEach(n => n * 2);   // returns undefined
const b = nums.map(n => n * 2);        // returns [2, 4, 6]

console.log(a);      // undefined
console.log(b);      // [2, 4, 6]
console.log(nums);   // [1, 2, 3]  — unchanged either way

When to Use Which:

Use forEach when:

  • You want to do something with each element without producing a new array
  • Side effects: logging, updating the DOM, saving to a database, sending analytics
// Good use of forEach — side effect (logging):
users.forEach(u => console.log(u.name));

// Good use — DOM update:
buttons.forEach(btn => btn.addEventListener("click", handler));

Use map when:

  • You want to transform the array into a new one
  • You want to chain more methods after
// Good use of map — transforming data:
const names = users.map(u => u.name);

// Good use — rendering in React:
{items.map(item => <Item key={item.id} data={item} />)}
⚠️ Another key difference — you can't break out of forEach: 
// This does NOT work — return doesn't break the loop:
[1, 2, 3, 4, 5].forEach(n => {
  if (n === 3) return;   // ← this returns from THE CURRENT ITERATION only
  console.log(n);        // still runs for 4 and 5!
});
// Output: 1, 2, 4, 5

// If you need to break early, use a regular for loop or find/some/every.

⭐ 8. Method Chaining — filter().map().reduce()

▼
⭐ THE most powerful pattern in functional JavaScript. You'll write this pattern hundreds of times in real React and Node.js code. Master it.

The Setup — Real-World Data:

const users = [
  { name: "Parth", age: 25, active: true },
  { name: "Deepika", age: 30, active: false },
  { name: "Rahul", age: 22, active: true },
  { name: "Kavya", age: 28, active: true }
];

// Task: Sum the ages of only the ACTIVE users
const totalActiveAge = users
  .filter(u => u.active)          // keep only active
  .map(u => u.age)                 // extract age
  .reduce((sum, age) => sum + age, 0);  // sum them

console.log(totalActiveAge);   // 75

Why This Chain Works — Trace-Through:

Step 1: Start with the original users array.

users = [
  { name: "Parth",   age: 25, active: true  },
  { name: "Deepika", age: 30, active: false },
  { name: "Rahul",   age: 22, active: true  },
  { name: "Kavya",   age: 28, active: true  }
]

Step 2: .filter(u => u.active) returns a NEW array with only active users.

afterFilter = [
  { name: "Parth", age: 25, active: true },
  { name: "Rahul", age: 22, active: true },
  { name: "Kavya", age: 28, active: true }
]

Step 3: .map(u => u.age) is called on THAT new array. It returns another new array of just the ages.

afterMap = [25, 22, 28]

Step 4: .reduce((sum, age) => sum + age, 0) is called on the map's output.

afterReduce = 0 + 25 + 22 + 28 = 75
🔑 Why chaining works: Both filter and map return arrays. Since arrays have .filter, .map, and .reduce methods on their prototype (Chapter 6!), you can call the next method directly on the previous method's return value. The chain literally reads like a data pipeline.

Common Chain Patterns You'll Use:

// Get names of active users
users.filter(u => u.active).map(u => u.name);

// Get emails of users older than 18
users.filter(u => u.age > 18).map(u => u.email);

// Sum of prices for items in stock
items.filter(i => i.inStock).reduce((sum, i) => sum + i.price, 0);

// Count of premium users
users.filter(u => u.plan === "premium").length;

Same Result — Reduce ONLY (Advanced):

The chain filter().map().reduce() can always be rewritten as a single reduce(). Sometimes this is more efficient (only one pass through the array) but usually less readable:

// Chain version (readable):
users.filter(u => u.active).map(u => u.age).reduce((s, a) => s + a, 0);

// Single reduce version (one pass):
users.reduce((sum, u) => u.active ? sum + u.age : sum, 0);

// Both return 75. Chain wins for readability. Single reduce wins for huge arrays.
🎯 Interview tip: Prefer chaining for readability. Only rewrite as a single reduce if performance profiling shows it's needed. Readable code beats clever code 9 times out of 10.

⭐ 9. Implementing map, filter, reduce Yourself (Polyfills)

▼
⭐ Hot interview question: "Implement your own map / filter / reduce from scratch." If you can write these without looking, you truly understand HOFs. Bonus: this ties back to Chapter 6 (prototypes).

Implementation 1 — myMap:

Array.prototype.myMap = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    result.push(callback(this[i], i, this));
    //                    ↑        ↑    ↑
    //                    │        │    └── the whole array
    //                    │        └── the index
    //                    └── the current element
  }
  return result;
};

// Test it:
const nums = [1, 2, 3];
console.log(nums.myMap(n => n * 2));   // [2, 4, 6]
console.log(nums.myMap((n, i) => n + "_" + i));   // ["1_0", "2_1", "3_2"]

Why it works:

  • this inside the method refers to the array it's called on (dot rule, remember Ch 3?).
  • We create a new result array — never mutate the original.
  • We call the callback with 3 args (element, index, array) — matching native map's API.
  • We push whatever the callback returns.

Implementation 2 — myFilter:

Array.prototype.myFilter = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (callback(this[i], i, this)) {   // ← only push if predicate is truthy
      result.push(this[i]);
    }
  }
  return result;
};

// Test:
console.log([1, 2, 3, 4, 5].myFilter(n => n > 2));   // [3, 4, 5]

Key difference from map: we push only when the callback returns truthy. Otherwise we skip.

Implementation 3 — myReduce:

Array.prototype.myReduce = function(callback, initialValue) {
  let acc = initialValue !== undefined ? initialValue : this[0];
  const startIdx = initialValue !== undefined ? 0 : 1;

  for (let i = startIdx; i < this.length; i++) {
    acc = callback(acc, this[i], i, this);
  }
  return acc;
};

// Test:
console.log([1, 2, 3, 4].myReduce((a, c) => a + c, 0));   // 10
console.log([1, 2, 3, 4].myReduce((a, c) => a + c));       // 10 (no initial)

Notice the subtle handling of the initial value: if no initial is passed, we start with arr[0] as acc and begin the loop at index 1. This matches native behavior.

⚠️ Why you shouldn't do this in production: Extending built-in prototypes (like Array.prototype) can cause naming collisions with future JS spec additions or third-party libraries. Prefix your polyfills with something unique (myMap, __customMap) or use standalone functions.

Bonus — Chaining Your Own Implementations:

const result = [1, 2, 3, 4, 5]
  .myFilter(n => n % 2 !== 0)   // [1, 3, 5]
  .myMap(n => n * 10)             // [10, 30, 50]
  .myReduce((s, n) => s + n, 0);  // 90

console.log(result);   // 90

Because your polyfills return real arrays, they chain the same way native methods do. Prototypes in action! 🎯

10. HOFs + Closures — The Function Factory Pattern

▼

HOFs get truly powerful when combined with closures. This is where you saw the multiplier pattern (Q8):

function multiplier(factor) {
  return function(number) {
    return number * factor;   // ← closes over `factor`
  };
}

const double = multiplier(2);
const triple = multiplier(3);
const times10 = multiplier(10);

console.log(double(5));    // 10
console.log(triple(5));    // 15
console.log(times10(5));   // 50

What Just Happened — Two Concepts Combined:

  1. First-Class Functions: multiplier is a HOF because it returns a function.
  2. Closures: The returned inner function remembers the factor variable from its parent's scope — even after multiplier() has finished executing and its EC is destroyed.

Memory Visualization:

After: const double = multiplier(2);

// multiplier(2) has finished executing. Its EC is destroyed.
// But `double` is still around, and its closure holds onto `factor = 2`.

CLOSURE OF double:
┌────────────────────┐
│ factor: 2          │  ← preserved from multiplier's dead EC
└────────────────────┘
         ↑
         │
      double  ── when called with 5, computes 5 * factor = 5 * 2 = 10

Using It With map — The Magic Combo:

const nums = [1, 2, 3, 4];

const doubled = nums.map(double);        // [2, 4, 6, 8]
const tripled = nums.map(triple);        // [3, 6, 9, 12]

// You can even skip the intermediate variable:
const times5 = nums.map(multiplier(5));  // [5, 10, 15, 20]

Look at nums.map(multiplier(5)) — this reads beautifully:

  • multiplier(5) returns a function that multiplies by 5
  • nums.map(...) uses that function to transform each element
🔑 The Pattern's Name: This is called a Function Factory — a HOF that produces specialized functions on demand. It's the foundation of currying (which you'll formally cover in Ch 6.5).

Real-World Function Factory Examples:

// A "greater than X" filter factory:
const greaterThan = (min) => (n) => n > min;

const nums = [1, 5, 10, 15, 20];
nums.filter(greaterThan(10));   // [15, 20]
nums.filter(greaterThan(5));    // [10, 15, 20]

// A "field extractor" factory:
const pick = (field) => (obj) => obj[field];

const users = [{ name: "Parth" }, { name: "Deepika" }];
users.map(pick("name"));   // ["Parth", "Deepika"]

// A "prefix" factory:
const prefix = (str) => (val) => str + val;

const nums = [1, 2, 3];
nums.map(prefix("#"));   // ["#1", "#2", "#3"]

Each of these is HOFs + closures in action. You'll write these constantly in production React code.

11. Real-World Patterns You'll Use Every Day

▼

Pattern 1 — Rendering Lists in React

function UserList({ users }) {
  return (
    <ul>
      {users.map(u => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  );
}
// map is used to transform data → JSX elements. Most common HOF in React.

Pattern 2 — Search / Filter UI

const filteredUsers = users.filter(u =>
  u.name.toLowerCase().includes(searchQuery.toLowerCase())
);
// Used in every search box you've ever seen.

Pattern 3 — Total Calculation

const cartTotal = cartItems.reduce((sum, item) => sum + item.price * item.qty, 0);
// Standard shopping cart pattern.

Pattern 4 — Group By

const users = [
  { name: "Parth",   dept: "Cloud" },
  { name: "Rahul",   dept: "AI" },
  { name: "Deepika", dept: "Cloud" }
];

const grouped = users.reduce((acc, user) => {
  if (!acc[user.dept]) acc[user.dept] = [];
  acc[user.dept].push(user);
  return acc;
}, {});

// {
//   Cloud: [{ name: "Parth", ... }, { name: "Deepika", ... }],
//   AI:    [{ name: "Rahul", ... }]
// }

Pattern 5 — Flattening

const nested = [[1, 2], [3, 4], [5]];

const flat = nested.reduce((acc, curr) => acc.concat(curr), []);
console.log(flat);   // [1, 2, 3, 4, 5]

// Or use the modern built-in:
nested.flat();   // [1, 2, 3, 4, 5]

Pattern 6 — Extracting IDs for API Calls

const selectedIds = selectedUsers.map(u => u.id);
await api.deleteUsers(selectedIds);

Pattern 7 — Chained Sort + Filter + Map

const displayNames = users
  .filter(u => u.active)
  .sort((a, b) => a.name.localeCompare(b.name))
  .map(u => u.name);
// Active users, sorted alphabetically, just their names.
💡 Once you internalize these 7 patterns, you'll spot them everywhere. Real production code is 60% these patterns combined in different ways.

12. Common Gotchas & Pitfalls

▼

Gotcha A: Forgetting to return in map

const nums = [1, 2, 3];

// ❌ WRONG — no return
const doubled = nums.map(n => {
  n * 2;   // just an expression, not returned
});
console.log(doubled);   // [undefined, undefined, undefined]

// ✅ RIGHT
const doubled = nums.map(n => {
  return n * 2;
});
// or the concise arrow:
const doubled = nums.map(n => n * 2);

Gotcha B: reduce on empty array without initial value

[].reduce((a, c) => a + c);      // 💥 TypeError: Reduce of empty array with no initial value
[].reduce((a, c) => a + c, 0);   // ✅ 0 (safe)

// Rule: ALWAYS pass an initial value to reduce.

Gotcha C: Can't break out of forEach or map

// You can't stop iteration mid-way:
[1, 2, 3, 4, 5].forEach(n => {
  if (n === 3) return;   // returns from THIS iteration, not the loop
  console.log(n);        // prints 1, 2, 4, 5
});

// If you need early exit, use for...of, some(), every(), or find():
for (const n of [1, 2, 3, 4, 5]) {
  if (n === 3) break;   // ✅ this works
  console.log(n);       // prints 1, 2
}

Gotcha D: map when you should use forEach (or vice versa)

// ❌ Anti-pattern: using map when you don't use the result
users.map(u => console.log(u.name));   // creates an array of undefineds for nothing!

// ✅ Use forEach for side effects only:
users.forEach(u => console.log(u.name));

// ❌ Anti-pattern: using forEach and manually pushing
const names = [];
users.forEach(u => names.push(u.name));

// ✅ Just use map:
const names = users.map(u => u.name);

Gotcha E: reduce that returns nothing

// ❌ WRONG — forgot to return acc
const total = nums.reduce((acc, curr) => {
  acc + curr;   // returns undefined
}, 0);
// TypeError on iteration 2: undefined + curr → NaN

// ✅ RIGHT
const total = nums.reduce((acc, curr) => {
  return acc + curr;
}, 0);

Gotcha F: Chain order matters

// Different order = different result!

// Filter first, then map — efficient (smaller array to map over):
users.filter(u => u.active).map(u => u.name);

// Map first, then filter — inefficient (map on ALL users first, then filter):
users.map(u => u.name).filter(name => name.startsWith("P"));
// (this one is fine too, just less efficient with huge arrays)

// Rule: filter EARLIER to reduce work in later steps.

14. Interview Answer Templates

▼

Q: "What is a higher-order function?"

"A higher-order function is a function that either takes another function as an argument or returns a function. This is possible in JavaScript because functions are first-class citizens — they can be treated like any other value. Common examples include map, filter, reduce, setTimeout, and event listeners. HOFs enable functional programming patterns like abstracting iteration logic away from business logic."

Q: "What's the difference between map and forEach?"

"Both iterate over an array without mutating it. The key difference is what they return: map returns a new array of transformed values, so you use it when you want to transform data. forEach returns undefined, so it's used for side effects like logging or updating the DOM. Because map returns an array, you can chain more methods on it. forEach can't be chained."

Q: "Explain reduce."

"reduce collapses an array into a single value. It takes a callback with two main parameters — accumulator and currentValue — plus an initial value as the second argument. The accumulator carries the result forward through each iteration. Reduce is powerful because that 'single value' can be anything: a number, a string, an object, or even a new array. Common uses include summing, finding max/min, grouping, and counting occurrences. Always pass an initial value to safely handle empty arrays."

Q: "Implement your own map function."

"I'd add it to Array.prototype as myMap. Inside, I'd create an empty result array, loop through this (which refers to the array the method is called on), call the callback with element, index, and array as arguments, and push whatever it returns into the result. Finally I'd return the result. This mirrors native map's behavior — same length as input, never mutates the original."

Q: "Why does arr.filter().map().reduce() work?"

"Because filter and map both return new arrays. Arrays inherit their methods from Array.prototype, so the returned arrays have filter, map, and reduce available on them too. Each method in the chain operates on the result of the previous method. It's essentially a data pipeline: filter narrows the data, map transforms it, reduce collapses it to a final value. This is why chainable methods are so common in functional programming."

Q9 — Answer

Array.prototype.myFilter = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (callback(this[i], i, this)) {
      result.push(this[i]);
    }
  }
  return result;
};

// Test:
console.log([1, 2, 3, 4, 5].myFilter(n => n > 2));   // [3, 4, 5]

Key points:

  • this refers to the array the method is called on (the dot rule from Chapter 4).
  • Create a new empty result array — never mutate the original.
  • Only push if the predicate returns truthy.
  • Pass (element, index, array) to match native filter's callback API.

Q10a — The nested reduce:

  1. Outer reduce iterates over each order. Accumulator is the running total.
  2. For each order, the inner reduce computes the sum of all item prices in that order.
  3. That inner sum is added to the outer total.
Order 1: Parth's items → 200 + 20 = 220        total: 0 + 220 = 220
Order 2: Deepika's items → 500                  total: 220 + 500 = 720
Order 3: Parth's items → 1200                   total: 720 + 1200 = 1920
Order 4: Rahul's items → 200 + 300 = 500        total: 1920 + 500 = 2420

Q10b — Group by user: Same pattern as counting occurrences (Q7), but we're accumulating totals instead of increments. Notice how the same user "Parth" appears twice in orders, and the reduce correctly adds both order totals under the same key.

This nested reduce pattern is extremely common in real backend/BI code. If you can trace this comfortably, you've mastered functional data transformation.
